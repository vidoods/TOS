# Инструкции по проекту TOS (Trading/Task Operating System)

Ты — эксперт-разработчик, работающий над проектом TOS. Это веб-приложение на стеке PHP (Backend) и JS/Chart.js (Frontend).

## Структура проекта и навигация

При решении задач ориентируйся на следующую архитектуру:

1. **Backend & API (`/api`)**:
   - `api/db.php`: Все операции с базой данных и подключение. Изучи этот файл перед написанием SQL-запросов.
   - `api/api.php`: PHP-роутер (только `switch` с `case`). НЕ пиши бизнес-логику здесь напрямую.
   - `api/handlers/`: PHP-обработчики, сгруппированные по темам (например, `auth.php`, `trades.php`, `plans.php`). Вся бизнес-логика находится здесь.

2. **Интерфейс (`/views`)**:
   - PHP-шаблоны страниц. Для добавления новых страниц необходимо создать шаблон в `/views/`, затем добавить роутинг в главном файле `index.php`.

3. **Frontend Ресурсы (`/assets`)**:
   - `assets/modules/`: Модульная структура JavaScript (пришла на смену массивному монолиту `app.js`, который теперь в архиве). Включает `core.js` (Quill, тултипы и пр.), `init.js` (DOMContentLoaded и роутинг), а также файлы для каждого раздела (например, `goals.js`).
   - `assets/scss/`: Рабочие файлы стилей (SCSS). **ЗАПРЕЩАЕТСЯ** редактировать скомпилированный `assets/style.css` напрямую. Цвета и отступы хранятся в `_variables.scss` (`var(--glass-bg)`, `var(--accent-blue)` и др.). Структура разбита на мелкие парциалы.
   - `assets/chart.js`: Логика отрисовки графиков.

## Технологический стек
- **PHP**: Процедурный и модульный подход для обработки данных.
- **Frontend**: SCSS для современных стилей, Chart.js для визуализации, Quill.js для редактора заметок, Toastify для уведомлений.
- **Данные**: Обмен данными между фронтендом и бэкендом идет через AJAX-запросы к `api/api.php`, который перенаправляет запросы к обработчикам из папки `api/handlers/`.

## Правила работы с кодом
- При модификации UI в папке `views/`, создавай обработчики в новых JS-модулях в `assets/modules/` и подключай их в `index.php` (перед `init.js`).
- При изменении стилей редактируй только SCSS файлы из папки `assets/scss/`. Используй системные CSS-переменные для цветов.
- Если нужно изменить логику сохранения данных, ищи нужный файл обработчика в папке `api/handlers/`.
- Перед добавлением новых модулей, стилей или страниц актуализируй свои знания через файл `GUIDE.md` в корне проекта.
